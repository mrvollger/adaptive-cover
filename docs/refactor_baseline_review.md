## 2. Assessment of the three plans
Plan 1 (house-model): best end state (pure settings/resolve.py, runtime/ 12 components, typed event queue; ControlState makes 'not restored' explicit; deletes coordinator.py/calculation.py/sun.py, drops pandas/numpy/pytz; pyright strict on engine/settings/runtime in CI; strongest migration tests: crash injection, idempotency, sanitized .storage; contract_v2 + M44-M49). Gaps: never names clock/service-caller/state-reader seams; no requirement of fake-driven unit tests per component; does not repair CI although 'CI enforces pyright and mutations' is impossible while CI is red; nothing on release automation, HA version matrix, translations, docs; P4 is XL; legacy and subentry paths coexist 2 releases.
Plan 2 (UI-first): best at reducing test coupling: P0 adds WindowHandle finding entities by role keyed by cover, removing the 48 hass.data reads and coordinator-attribute reads before anything moves; spec-generated service tests; spec round-trip property test; equivalence replay 15 windows x 4 dates; deletion drill (remove implementation tier, behavior tier must still kill 43/43); contract table mapping each change to its test migration; entry.runtime_data; explicit P6 cleanup. Gaps: P1 adds services, categories, card on top of the 1,937-line coordinator before the split (new coupling to rework); no clock injection; no CI/release/HA-matrix/translation/docs work.
Plan 3 (risk-first): strongest gate machinery: contract ledger; behavior_tier_ids.txt (CI fails if a behavior test disappears without a ledger entry); make_patches --check; house-replay goldens pinning the outbound command timeline; deletion drill every phase; mutation runs on PRs. Only plan making the clock an input to runtime/. Coordinator split as ~8 move-only PRs each tied to named mutation IDs (e.g. GatePolicy -> M01-M07). pyright in CI in P0. Gaps: heaviest transition burden (dual-written group, legacy flat keys, resolved snapshot until P7); 10+ releases, 48 h soaks, a week in shadow mode; subentries optional so two config models may persist; pyright strict only runtime/; assumes a --check flag that doesn't exist yet.
Verdict: Plan 1's target design + Plan 3's gate machinery and move-only split + Plan 2's P0 test retargeting and spec-generated tests. NONE fixes the red CI, release automation, HA version compatibility, translations, or contributor docs; the final plan must add these as a Phase 0 prerequisite.
